# HTML reading and presentation design

Read when creating or revising the visual artifact. Preserve the agreed type, teaching depth and user style.

## Compose the reading hierarchy

The default combines a dark blue opening, restrained gradient and light, clearly separated reading sections. Soft background light, fine grids and arcs provide presentation hierarchy without competing with text. Keep the decorative background static.

Use Fandol Song for Chinese prose, Fandol Hei for headings and figure labels, and Fandol Fang for Chinese code. The supplied web fonts preserve regular and bold forms and are embedded as document subsets. English HTML prose uses a Times-like serif, labels use Arial, and code uses a system monospace. The LaTeX template retains its TeX Gyre families.

Keep continuous explanations in paragraphs. Use cards for parallel comparisons, inputs/outputs or exercises, not every sentence. Use readable line lengths, spacing and restrained emphasis. Inspect actual mobile type and figure labels instead of relying on nominal sizes.

## Make figures answer a question

Use a concrete example to expose a difficulty, a pipeline or system diagram to explain operations, and a data chart to support an observation. Do not force paper figure counts or numbering onto a tutorial.

Show input, operation, state and output. Match names to prose, separate responsibilities and label arrows. Use editable SVG for suitable diagrams and standard plotting tools for scientific data. Inspect original figures and crops before describing them.

Keep typography, spacing, line weight and panel hierarchy consistent. Color should have a stable meaning and a second encoding through labels, patterns or shapes. ColorBrewer and Viridis can guide categorical and sequential choices. No fixed point size or caption-relative ratio is universal.

Begin captions with the relationship or supported observation, then add necessary conditions and provenance. Preserve axis units, scales, comparison conditions and actual uncertainty. Do not invent error bars or animate a claimed improvement without data.

## Control notes and interaction

Use compact citations near supported claims and consolidate repeated sources in a final disclosure. Notes should add information needed for interpretation or checking. Figure conditions and video timestamps remain visible.

Keep essential reasoning expanded; hints and solutions can use native details/summary. Use clear labels, visible keyboard focus and code copying where useful.

Use references/animation.md for stages, flow, sampling and parameter effects. Graphics, numbers and explanations must use the same state. Provide pause and manual exploration, a readable static state, and reduced-motion behavior.

On narrow screens, preserve explanation order and permit local scrolling for wide diagrams, equations and tables. Avoid whole-page overflow. Inspect print separately when delivered, with full solutions and meaningful static comparisons.

Place figures outside concept and warning callouts. For a short high-value dialogue, retain speaker labels and source time and explain its teaching role; do not fill the lesson with transcript blocks.
